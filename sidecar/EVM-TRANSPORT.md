# Sepolia RPC transport

The enclave-local HTTP service exposes POST `/evm/read`, `/evm/send`, and `/evm/receipt` alongside existing FHE routes. It binds to 127.0.0.1, rejects browser origins and remote hosts, and routes Ethereum JSON-RPC **only** through the local Nym SOCKS5h listener. TLS verification and hostname resolution remain inside the Nym path. No direct-network fallback, HTTP redirect, or automatic retry exists in this transport.

This PoC explicitly trusts the configured Sepolia node. `trust: "explicitly_trusted_rpc"` means node-reported data; neither TLS nor agreement among JSON-RPC responses establishes independent Ethereum consensus.

All requests require `chainId: "11155111"`. The sidecar checks `eth_chainId` before every operation. Inputs are limited to 512 KiB, RPC responses to 1 MiB, signed envelopes to 128 KiB, log queries to 256 blocks and 1024 returned logs. Entire sidecar operations have a 120-second deadline; Rust permits 130 seconds for the local HTTP exchange. Errors are fixed codes and contain no upstream diagnostic payloads.

- `/evm/read`: `{chainId, method, params}` returns `{chainId, trust, result}`. Allowed methods: eth_call, eth_getCode, eth_getLogs, eth_getBlockByHash, eth_getBlockByNumber, eth_getTransactionCount, eth_estimateGas, eth_gasPrice, eth_maxPriorityFeePerGas. call/code/estimate require `{blockHash, requireCanonical:true}`. Logs require explicit block hash or bounded numeric endpoints plus address/topics. Blocks return hash, number, parentHash and timestamp. Pending nonce is allowed as a node observation, not a nonce reservation.
- `/evm/send`: `{chainId, rawTransaction, expectedHash}` validates signed legacy/EIP-2930/EIP-1559 bytes and submits those bytes exactly once. Returns `{chainId, hash, outcome:"accepted"}` only when the RPC acknowledges the exact hash. After send, errors/timeouts or a different returned hash yield `outcome:"ambiguous"` with a fixed reason. Acknowledgement does not establish inclusion or successful execution.
- `/evm/receipt`: `{chainId, hash}` returns `{chainId, trust, receipt, finality, finalizedHead}`. `finality` is `not_found`, `included`, or `finalized`. A receipt must match its transaction/log scopes and the node's canonical header at its height; its height is compared to the node's finalized head. Status 0 remains a reverted receipt even when finalized. A missing receipt never proves rejection or permits replacement. Consumers must verify their expected contract/event and reconcile actual encrypted results.

Rust `zz_zama::evm::SignedTransaction::from_signed_bytes` checks signature/chain and computes the hash; `restore(bytes, expected_hash)` enforces journal integrity. The caller must durably store bytes, hash and operation binding **before** `Client::submit_journaled`. Transport has no signer, nonce allocator, fee bumper or replacement path. Lost/malformed local HTTP responses also return `SubmissionOutcome::Ambiguous` with the original hash. Poll `receipt` and retain the original journal; the transport neither resends nor advances an application cursor.

`Client::read<T>(ReadMethod, params)` returns typed deserialization of a tagged observation; `call` provides a hash-pinned ABI-call helper. `ReceiptObservation` validates consistent receipt/log/finality fields. Higher-level ABI decoding, enclave signer access, durable journal transitions and orchestration are separate caller responsibilities. These routes do not expose keys, encrypt inputs, create transactions or authenticate Monero consensus.

Local tests use an injected RPC and loopback SOCKS fixtures; they send no transaction to any real network.
